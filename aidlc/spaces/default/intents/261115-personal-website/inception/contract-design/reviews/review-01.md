### Summary

The contract set matches the unit DAG: one row per edge plus the external surface. The redirect semantics in C4 match how `local-server.mjs` handles requests today: it decodes the path once, fetches `/graph.json` by absolute path, and its file lookup, which runs after any redirect, returns 404 for removed tags. Three gaps would cause rework before approval. The fixture-vault layout that C1's callers assume does not exist, and every current test scans the root that `Pages/` would be added to. The "reads only NOTES and PAGES" boundary is contradicted by the upward attachment lookup, and the contract does not say whether page images are published. Nothing in the contract names what writes `_redirects.json`, and the obvious Astro endpoint for it would not be built.
