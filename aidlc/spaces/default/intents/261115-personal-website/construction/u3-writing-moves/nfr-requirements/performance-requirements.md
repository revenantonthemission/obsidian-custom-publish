# Performance Requirements — U3 `u3-writing-moves`

Upstream: `inception/requirements-analysis/requirements.md` (NFR1, NFR4, NFR6); `construction/u3-writing-moves/functional-design/functional-spec.md`, `rules.md` (BR1.1–BR1.3, BR2.1–BR2.4, BR3.1–BR3.5, BR4.1–BR4.4); `inception/contract-design/contract-summary.md` (C4, C5); codekb `technology-stack.md`.

U3 is the first unit in this release that runs code at request time. The static server gains a redirect lookup in front of its file lookup, and the build writes one extra file into its own output directory. The moved pages themselves change only their address and one back link, so their page-load budgets carry over unchanged; the new costs are the table's production and the lookup's per-request price.

## Notes

- The redirect answer itself is cheap by construction: one map lookup on a decoded path (NFR4.10). The 301 is answered before the file lookup, so a redirected request does no file work at all.
- The table grows with the tag count, not with the traffic: one rule per tag page. The vault's tag count is small and the file is read only when it changes, so no capacity work follows from U3.
- The moved pages keep their existing stylesheets and islands, so the page-load budgets are the ones the HIG performance suite already enforces (NFR6.12); the only new markup is the back link (NFR6.14).
- No wall-clock build-time comparison is required: the repository records no build-time baseline, so NFR6.13 states a file-count and budget check the repository can run today instead of a percentage band with no method behind it.
