### Summary

The design is sound on the points that matter most: the marker rule is a pure, segment-aware, case-sensitive path function that matches contract C3 exactly (including trailing slash, query, percent-encoded Korean and fail-closed invalid paths), the one-item model and the `page` / `true` / absent vocabulary are consistent across the spec, rules, components and screen-state tables, the phone sheet is already a static disclosure so the no-JavaScript and 320 px claims hold, and every upstream AC has an honest traceability row. The one thing to fix before implementation is the existing-test inventory: two suites the design never mentions (`profile-presentation.test.ts` and `crossunit.spec.ts`) assert the four-item header in rendered HTML and with JavaScript off, so `just crossunit` and `npm run test:unit` fail on the U4 merge unless the design names the new expectations for them; the two Minor findings are precision issues in BR2.3's route scope and in how `ariaCurrent` is derived.
