> R-01 Reviewer note: The change list now names `hig-pages.spec.ts`, the four homepage test files and the rewritten W5 block, so the gate is no longer blocked by stale `.home-card` checks. The NFR1-b part is still open. The named subject, `==[[Simple Post]]==` in `fixtures/vault/Notes/Post With Formatting.md`, does not render as a highlighted link with today's transform. `preprocessor/src/transform.rs` runs `convert_wikilinks` (line 74) before `convert_highlights` (line 81). The link therefore becomes `==<a href="/posts/simple-post">Simple Post</a>==` first. `HIGHLIGHT_RE` is `==([^=n]+?)==` (line 17) and cannot match across the `=` in `href=`. Running that regex on this string leaves it unchanged, with no `<mark>`. The moved NFR1-b test would find no `mark a` in the fixture post, so it would either fail or need DOM injection again. Required action: either list a transform change in Code Generation (run highlights before wikilinks, or let the highlight match an `<a …>` span) with a Rust test showing `==[[Simple Post]]==` becomes `<mark><a href="/posts/simple-post">…</a></mark>`, or choose a fixture form that renders `<mark><a>` today.
